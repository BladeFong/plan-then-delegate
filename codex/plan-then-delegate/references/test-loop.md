# 任务测试循环（F-V）

文中 F = 修复代理、V = 测试代理。Codex 的 `send_input` 为原生工具，无需额外功能开关。

## 触发与基本结构

由 SKILL.md 第 3 节任务闭环触发：当前任务 R 审查通过后（未启用审查循环时为 F 完成并通过轻量校验后），主代理判定该任务需要测试时进入本流程。

进入本流程后，当前任务的实现子代理作为修复代理 F，主代理传给 F 的 message 使用 F 模板。

**严格串行**：任何时候只有一条任务流水线在跑；本任务的 F-V 循环完整闭环后，当前任务才算闭环，才进入下一个任务。

**禁止空起 V**：主代理判定该任务无需测试时，不进入本流程，不得为此冷启动 V。V 必须有明确的改动范围才能启动，给不出范围就不起。

## 单对 F-V 循环（主代理中继）

1. 主代理冷启动 V（前台串行），传入 F 的改动范围摘要。
2. V 向主代理报告。
3. 主代理校验：
   - 全绿 且 无业务代码问题 → 该任务验收通过、闭环，进入下一个任务
   - 有失败 / 暴露业务代码问题 → 主代理 `send_input` F 修复 → F 修复 + 自跑编译后返回 → 主代理 `send_input` V 复验 → 回到第 2 步

## 回审兜底（本轮启用过审查循环时）

仅当本轮启用了审查循环、主代理保存了当前任务配对审查代理 R 的句柄时适用。

F 在本轮测试循环中的业务代码修复：

- **小修**（定点修复明确 bug、补边界判断等） —— 由 V 的测试验证兜底，不回审，任务直接闭环
- **较大结构改动**（多函数联动改动、新增公共接口、调用链调整等） —— 把修复文件与要点发原 R（`send_input` 接力）增量复审，R 更新结论为「通过」后任务才闭环；R 仍不通过，按 SKILL.md 第 3 节的返工流程处理

本轮未启用审查循环时，本节不适用——V 的测试验证即最终结论。

## send_input 用法

- 给已存在子代理派后续任务，用 `send_input` 直接接力；**不**冷启动重复 Agent —— 冷启动丢上下文、token 翻倍
- 仅当代理"上下文坏 / 用户要求重启"或续接失败（报找不到目标类错误，如跨 Fork、客户端重启）时，才冷启动新代理接手，prompt 带全任务背景与此前结论摘要
- message 自含任务相关字段即可；子代理已读过对应 references，不必重述规则

## V 模板

（必填字段不可省，可选字段按需）

```
[可选，冷启动子代理时需要]
你是 plan-then-delegate 的「测试代理 V」。请先用 Read 读取执行规则：
~/.codex/skills/plan-then-delegate/references/agent-test.md
读取失败立即返回固定文案「references 读取失败」并停止。

## 本轮修复代理 F 的改动范围  [必填]
- 修改文件：<file_list>
- 改动要点：<key_changes_from_F_report>

## 特殊测试命令  [可选]
<覆盖默认；通常不填>
```
