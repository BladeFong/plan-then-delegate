# 补充测试循环

详细规则。仅当主代理工具列表中存在 `SendMessage` 工具时启用；否则主代理跳过本节，直接进入 SKILL.md 第 5 节。

文中 F = 修复代理、V = 测试代理。

## 触发与基本结构

所有实现子代理完成报告后，主代理主动询问用户："是否要进行补充测试？" 用户同意才进入本流程。

进入本流程后，实现子代理作为修复代理 F，主代理传给 F 的 prompt 使用 F 模板。

**严格串行**：一个 F-V 对的测试循环（含其修复迭代）完整闭环后，才进入下一对；任何时候只有一对在跑。

## 单对 F-V 循环

对于每个修复代理 F：

1. 主代理根据 F 的改动判断，如果有必要测试，则冷启动测试代理 V（前台串行），传入 F 的改动范围摘要；如果主代理判断没有必要测试，则直接视为该 F-V 对通过。
2. V 给主代理报告
3. 主代理校验：
   - 全绿 且 无业务代码问题 → 该对验收通过，处理下一对
   - 有失败 / 暴露业务代码问题 → 主代理 `SendMessage` F 修复 → F 修复 + 自跑编译后，主代理 `SendMessage` V 复验 → 回到第 2 步

所有 F-V 对都通过验收后，进入 SKILL.md 第 5 节。

## SendMessage 用法

- 给已存在子代理派后续任务，用 `SendMessage(to: agentId, ...)` 直接接力；**不**冷启动重复 Agent —— 冷启动丢上下文、token 翻倍
- 仅当代理"上下文坏 / 用户要求重启"时才冷启动新代理接手
- message 自含任务相关字段即可；子代理已读过对应 references，不必重述规则

## V 模板

（必填字段不可省，可选字段按需）

```
[可选，冷启动子代理时需要]
你是 plan-then-delegate 的「测试代理 V」。请先用 Read 读取执行规则：
~/.claude/skills/plan-then-delegate/references/agent-test.md
读取失败立即返回固定文案「references 读取失败」并停止。

## 本轮修复代理 F 的改动范围  [必填]
- 修改文件：<file_list>
- 改动要点：<key_changes_from_F_report>

## 特殊测试命令  [可选]
<覆盖默认；通常不填>
```

